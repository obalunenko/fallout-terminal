## Root Cause Analysis

The first reproduced boundary divergence is the installed application build, not
candidate serialization. The application at
`/Users/olegbalunenko/Desktop/Fallout Terminal.app` contained an executable
dated 2026-08-21 with SHA-256
`daa4208d2085d1eb3ea58cb2b9b016d7bbde501f56cbc34f9404aea475792a9c`.
Opening the exact authored-file copy in that build rendered the pre-grouping
flat terminal list with only per-terminal rename/delete actions. It exposed no
group creation or terminal-move action, so it could not construct, review, or
submit either the partial or complete BUG-003 repair candidate. By comparison,
the workspace binary present at reproduction time was dated 2026-08-25 with
SHA-256
`4ab3ef2ba53af53ebdf166c986a4c93540013ff29eff69d1e5bb3ad4d3f648c8`.

The prior BUG-003 investigation inferred the candidate from the error's group
IDs and then verified a minimized fixture through a disposable built-app path.
That evidence demonstrated how a particular partial candidate should be
classified, but it did not bind the original report to an executable. The
exact-build capture proves that the installed Desktop application was not
eligible acceptance evidence for the grouping fixes; the corrected path must
be rebuilt and exercised from an owned bundle before closure.
