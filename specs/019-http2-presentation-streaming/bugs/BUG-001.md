# Bug Report: Authoritative Movement Cues Intermittently Disappear over ngrok

**Type**: Untested flow
**Severity**: Medium
**Feature**: HTTP/2 Presentation Intent Streaming (`feature/019-http2-presentation-streaming`)
**Reported**: 2026-08-24
**Status**: Patched
**Patched**: 2026-08-25

## Description

When a player uses the authenticated ngrok URL, the menu-selection movement sound and the hacking
symbol/word movement sound sometimes stop playing. The application otherwise remains usable and
continues to accept session, broadcast, and public-access operations.

The supplied application log shows successful local startup, public-access startup at revision 12,
and broadcast startup. During the affected public session it repeatedly records
`http: proxy error: context canceled`, including after a broadcast end/start cycle. It records no
application operation failure and no audio-specific evidence.

The feature intentionally suppresses audio for controller-local transient targets and for
superseded intermediate authoritative targets. This report therefore concerns a missing cue for an
applicable final/current authoritative movement, or continued silence on later accepted movements,
not the expected omission of cues for targets that were superseded during a rapid sweep. The first
bugfix reproduction must make that distinction explicit.

## Root Cause Analysis

The confirmed root cause is a coverage gap, not yet a proven transport or audio implementation
fault. Menu movement and hacking movement both pass through `playControllerPresentationCue`, which
suppresses an authoritative cue while a newer valid local transient supersedes that canonical
presentation. The final matching canonical update is intended to clear the transient and emit one
cue. Existing tests verify that no more than two cues occur during a rapid sweep, but never require
the surviving final cue, so a reconciliation race that emits zero cues is invisible.

The repeated `context canceled` proxy messages are consistent with request-stream cancellation,
idle rotation, replacement, browser disconnect, or fallback. Their timing makes the
stream-cancellation/reconciliation path a priority reproduction target, but the log alone does not
prove causation. Audio manifest, fetch, decode, resume, and playback failures are deliberately
caught and made non-fatal in `sound.js`, so the supplied application log cannot distinguish an
expected transport cancellation from a lost cue or an audio-device/browser failure.
