# Bug Report: Repository-wide Go Checks Bypass the macOS Deployment Target

**Type**: Implementation drift

**Severity**: Low

**Feature**: `026-go-code-quality-refactor`

**Reported**: 2026-08-27

**Status**: Patched

**Patched**: 2026-08-27

**Verified**: 2026-08-27 — Fresh-cache `task test` and `task test:race` passed with zero linker target-version warnings.

## Description

The final verification used raw `go vet ./...`, `go test ./...`, and `go test -race ./...` commands on macOS. Those commands bypassed the repository-governed macOS 13 deployment environment and emitted linker target-version warnings even though all checks passed. The canonical Task targets already apply `MACOSX_DEPLOYMENT_TARGET=13.0` and matching CGO compile and link flags.

## Root Cause Analysis

The verification plan named raw Go commands instead of the repository's Task targets. On Darwin, the raw commands link against Go's default minimum target while Xcode 26.5 and project objects carry newer deployment metadata. The Taskfile already aligns `MACOSX_DEPLOYMENT_TARGET`, `CGO_CFLAGS`, and `CGO_LDFLAGS` with the supported macOS 13 baseline.

## Recommended Fix

1. Require canonical warning-free macOS Go validation in the specification.
2. Replace the raw repository-wide verification commands in the plan with Task targets.
3. Reopen T024, add contributor guidance, and rerun unit and race suites through the Taskfile.
4. Run the bugfix consistency check and record warning-free verification evidence.
