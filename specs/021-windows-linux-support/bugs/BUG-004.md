# Bug Report: Tagged Release and Completion State Are Incomplete

**Status**: Patched
**Patched**: 2026-08-26
**Type**: Spec gap / Artifact status drift
**Severity**: High
**Feature**: 021-windows-linux-support
**Reported**: 2026-08-26

## Description

The feature records the implemented four-target Windows/Linux SemVer-tag publication in T060 and
the release documentation, but `spec.md` has no normative acceptance scenario, requirement, or
success criterion for publishing tagged artifacts with GoReleaser v2 to GitHub Releases and GitHub
Packages. The previously recorded maintainer requirement says a tag release must build and publish
all supported targets. Now that `darwin/arm64` is explicitly part of the supported local
`package:all` set, the tagged release must also coordinate an unsigned macOS DMG whose eligibility
is verified only by its SHA-256 sidecar with the four Windows/Linux portable archives from one tag
source revision. The maintainer explicitly removed signing and notarization from the release gate.

The artifact status is also inconsistent. T055 is checked despite its owned native validation being
recorded as `NOT RUN`, T060 is checked although its current implementation publishes only the four
portable targets, and `.spec-context.json` says `completed` while T056–T058 and T062 remain pending.

- **Affected user story**: User Story 3 — Produce trustworthy artifacts for all targets.

### plan.md

- **False completions**: T055 did not execute the native validation it owns; T060 does not include

- **Missing tasks**: No additional task ID is required; reopen T055 and T060 with BUG-004 scope and
  preserve T056–T058/T062 as pending follow-up evidence.

### Companion context

- **Affected artifact**: `.spec-context.json`.
- **Gap identified**: Terminal `completed` status conflicts with pending and reopened tasks.
- **Required transition**: Reopen the completed feature for BUG-004 through the Companion writer so

## Root Cause Analysis

Tag publication was added late as a convergence task and mapped onto general artifact verification
requirements instead of being promoted into a first-class release requirement. At that time “all”
was interpreted as the four newly requested portable targets. Subsequent Darwin inclusion updated
the local aggregate but deliberately left remote/release behavior unchanged, exposing the original
gap. The feature was marked complete before later convergence tasks were appended.

## Recommended Fix

1. Run `/speckit.bugfix.patch BUG-004` to add the five-target tagged-release contract and reopen the
   false completions.
2. Reopen the completed Companion feature for BUG-004 through the repository writer.
3. Run `/speckit.bugfix.verify BUG-004` to confirm cross-artifact consistency.
4. Resume `/speckit.implement` to add the macOS tag job, joined publication, and native evidence.
