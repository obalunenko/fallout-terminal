# Historical Bug Report: Local Package-All Cannot Replace Previous Output

> Historical record from the constitution v6 implementation cycle. It was patched on 2026-08-26 and is preserved only as implementation history. Constitution v7.0.0 and the 2026-08-27 plan govern current behavior; do not use this report as active requirements or remediation instructions.

**Status**: Historical (Patched)
**Patched**: 2026-08-26
**Type**: Spec gap / Untested flow
**Severity**: High
**Feature**: 021-windows-linux-support
**Reported**: 2026-08-26

## Description

Running `task package:all` with its default output fails before Docker starts when `build/dist`
already exists:

```text
build: aggregate output already exists: ".../build/dist"
```

`build/dist` is the repository-owned default used by normal packaging and previous aggregate runs,
so requiring maintainers to move or delete it before every local matrix build makes the canonical
command non-repeatable. The current contract explicitly requires `OUTPUT` to be absent and therefore
matches the implementation but not the expected package workflow.

## Artifact Traceability

### spec.md

- **Affected user story**: User Story 3 — Produce trustworthy artifacts for all targets.
- **Affected requirements**: FR-018, FR-025, SC-010.
- **Gap identified**: No requirement defines safe replacement of a previous repository-owned local
  aggregate output or preservation of that output when the new attempt fails.

### plan.md

- **Affected sections**: Implementation Sequence step 13 and Local Docker aggregate verification.
- **Impact**: Publication needs a verified replacement transaction: retain the prior directory until
  the complete new matrix is ready, swap through a same-filesystem sibling work root, and restore on
  publish error.

### tasks.md

- **Affected tasks**: T061 and T062.
- **False completions**: None; previous-output replacement was not part of T061's written scope.
- **Missing tasks**: A new task is required to implement and contract-check repeatable publication
  while rejecting unsafe existing files, symlinks, repository roots, and unrecognized custom
  directories.

### Other design artifacts

- **contracts/package-cli.md**: Explicitly requires `OUTPUT` not to exist.
- **data-model.md**: Mentions collisions but does not define ownership recognition, backup, rollback,
  or safe replacement.
- **docs/platform-packaging.md / README.md**: Tell maintainers to choose a new directory or move the
  old result instead of making the canonical command repeatable.

## Root Cause Analysis

Atomic first publication was implemented as a directory rename guarded by
`ensureAggregateOutputAbsent`. The same guard remained after `package:all` became the canonical local
developer command, so output collision avoidance was mistaken for a permanent no-replacement policy.

## Recommended Fix

1. Run `/speckit.bugfix.patch BUG-002` to define safe repeatable local publication.
2. Implement the new task with same-filesystem backup and rollback plus unsafe-target guards.
3. Run `/speckit.bugfix.verify BUG-002` and execute the controlled checks in CI; no local
   four-target Docker build is required.
