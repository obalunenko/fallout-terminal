# Historical Bug Report: Local Package-All Omits Darwin

> Historical record from the constitution v6 implementation cycle. It was patched on 2026-08-26 and is preserved only as implementation history. Constitution v7.0.0 and the 2026-08-27 plan govern current behavior; do not use this report as active requirements or remediation instructions.

**Status**: Historical (Patched)
**Patched**: 2026-08-26
**Type**: Spec gap / Implementation drift
**Severity**: High
**Feature**: 021-windows-linux-support
**Reported**: 2026-08-26

## Description

`task package:all` currently produces the four Windows/Linux archives and runnable payloads but does
not include the existing supported `darwin/arm64` package produced by `task package`. The command's
name and intended maintainer workflow require all supported local targets, including the native
macOS application bundle.

Darwin packaging cannot be delegated to the Linux Docker images. The aggregate must therefore run
on the supported `darwin/arm64` host, execute the canonical no-target package plan natively, copy the
completed ad-hoc signed `Fallout Terminal.app` into `OUTPUT/bin/darwin-arm64/`, and then join it with
the four Docker-built Windows/Linux outputs. The remote native Windows/Linux release-evidence matrix
remains unchanged.

## Artifact Traceability

### spec.md

- **Affected user story**: User Story 3 — Produce trustworthy artifacts for all targets.
- **Affected requirements**: FR-015, FR-018, FR-025, SC-007, SC-010.
- **Gap identified**: Local aggregate requirements enumerate only four Windows/Linux targets and do
  not require the supported Darwin compatibility package.

### plan.md

- **Affected sections**: Summary, Implementation Sequence step 13, Local Docker aggregate evidence.
- **Impact**: The local command becomes a hybrid native-plus-Docker plan, validates `darwin/arm64`
  before mutation, reuses the canonical macOS package graph, stages the application bundle, and
  publishes it in the same replacement transaction as the portable matrix.

### tasks.md

- **Affected tasks**: T061–T063.
- **False completions**: None; Darwin inclusion was not part of their written scope.
- **Missing tasks**: A new task is required for native Darwin host validation, canonical package
  reuse, safe bundle copying/verification, CLI reporting, docs, and controlled tests.

### Other design artifacts

- **contracts/package-cli.md**: Says the macOS package does not join the four-target portable matrix.
- **contracts/artifact-layout.md**: Has no aggregate Darwin bundle path.
- **data-model.md**: Local aggregate owns exactly four Docker environments and four payloads.
- **README.md / docs/platform-packaging.md**: Document only four local executable paths.

## Root Cause Analysis

The feature originally interpreted “all” as the four newly requested Windows/Linux combinations
and treated Darwin as a separate compatibility path. The maintainer command was later promoted to
the canonical all-platform local package command without revisiting that exclusion.

## Recommended Fix

1. Run `/speckit.bugfix.patch BUG-003` to define the five-target local aggregate.
2. Implement native Darwin package staging through the existing package plan and publish it with the
   four Docker outputs.
3. Run `/speckit.bugfix.verify BUG-003`; keep native build/tests `NOT RUN` locally unless explicitly
   requested.
