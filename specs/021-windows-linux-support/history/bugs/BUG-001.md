# Historical Bug Report: Local Docker Aggregate Contract Is Incompletely Specified

> Historical record from the constitution v6 implementation cycle. It was patched on 2026-08-26 and is preserved only as implementation history. Constitution v7.0.0 and the 2026-08-27 plan govern current behavior; do not use this report as active requirements or remediation instructions.

**Status**: Historical (Patched)
**Patched**: 2026-08-26
**Type**: Spec conflict / Untested flow
**Severity**: High
**Feature**: 021-windows-linux-support
**Reported**: 2026-08-26

## Description

`task package:all` now builds the current checkout locally with Docker for all four Windows/Linux
targets and publishes both governed archives and directly accessible executable/resource payloads.
The detailed CLI contract and FR-025 describe that behavior, but the success criteria, plan, data
model, artifact-layout contract, Task command table, research decision, and validation coverage
still describe an archive-only or remote-native aggregate in whole or in part.

When Docker is unavailable, the contract also requires only a nonzero result; it does not require
an actionable diagnostic that preserves the Docker failure reason and tells the maintainer how to
recover. This allowed an uninformative Task precondition error to satisfy the written contract.

## Artifact Traceability

### spec.md

- **Affected user story**: User Story 3 — Produce trustworthy artifacts for all targets.
- **Affected requirements**: FR-017, FR-018, FR-025, SC-001, SC-004.
- **Gap identified**: FR-025 requires executable/resource payloads, but US3 and SC-001 measure only
  archives. FR-017 does not explicitly cover local packaging prerequisites such as Docker.

### plan.md

- **Affected sections**: Constitution Check, Implementation Sequence steps 12–14, Verification
  Strategy.
- **Impact**: The plan must distinguish local Docker static evidence from remote matching-host
  evidence, specify atomic `bin/<os>-<arch>/` payload publication, verify payload/archive identity,
  require actionable Docker prerequisite diagnostics, and remove stale governance text and duplicate
  step numbering.

### tasks.md

- **Affected tasks**: T061.
- **False completions**: None; T061 implemented payload export, but its artifact list omits the
  related contract/static verification surfaces.
- **Missing tasks**: A follow-up verification task is required for the four runnable payload paths,
  required resources, payload/archive byte identity, atomic failure behavior, and informative Docker
  prerequisite errors without requiring a local four-target build.

### Other design artifacts

- **data-model.md**: Build Host and Aggregate Packaging Run allow only remote native orchestration
  and do not model a local Docker matrix or runnable payload publication.
- **contracts/artifact-layout.md**: Defines archive contents but not the stable aggregate
  `bin/<os>-<arch>/` output tree.
- **contracts/task-runner.md**: Names `package:all` but omits its runnable output and failure contract.
- **research.md**: Records local Docker builds but not direct payload export and payload/archive
  agreement.
- **validation.md**: Contains native archive evidence only and no explicit local aggregate contract
  evidence.

## Root Cause Analysis

The aggregate command changed incrementally from remote GitHub dispatch to a local Docker matrix,
then gained direct executable/resource export. FR-025, T061, and `package-cli.md` were updated during
implementation, while the earlier archive/native-only design model and acceptance language were not
revisited as a complete artifact set.
