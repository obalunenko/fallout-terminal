# Tasks: Vue and TypeScript Frontend Migration

**Authority**: Fallout Terminal Constitution 9.0.0; approved `spec.md`, `plan.md`, `research.md`, `quickstart.md`, `migration-ownership.md`, both contracts, all clarifications, and the passing migration-readiness checklist. The immutable rollback source is commit `06696ee1c7155a1bb1135ef46ec91445dd73a2a4`.

**Execution rule**: The mandatory waves **a → b → c → d → e → f → g → h → i** override user-story priority where they conflict. Every task uses the format `Outcome · Files; Depends; Covers; Verify; Temporary`. In a `Files:` list, consecutive basenames following an exact directory-qualified path inherit that path's directory (for example, `frontend/client/src/components/A.vue`, `B.vue` means the exact paths `frontend/client/src/components/A.vue` and `frontend/client/src/components/B.vue`). `Temporary: none` means the task creates no coexistence mechanism. Generated protobuf and Wails output is changed only by its governed generator. Browser tests remain `.mjs`; visual snapshots are immutable and are never approved or regenerated merely for Vue.

**Canonical workflow rule**: The root `Taskfile.yml` is the only documented frontend workflow. npm workspace commands are Task-owned implementation details and are not a competing direct workflow.

## User-story delivery map

| User story | Primary waves | Independently testable result |
|---|---|---|
| US1 — Players retain the complete terminal experience | f–h | Production `#playerApp` passes connection, multi-tab, reconnect, navigation, hacking, timing, sound, uplink, accessibility, and immutable visual journeys. |
| US2 — The Overseer retains every privileged control | c–e | Production `#overseerApp` passes every privileged browser journey plus separate Wails/native/embed/resource/package evidence. |
| US3 — Operators retain secure deployable applications | b, e, h, i | Separate reproducible bundles and all five matching-host packages retain the existing trust, embed, resource, startup, and capability contracts. |
| US4 — Maintainers work in two strictly typed component applications | a–i | Both applications and generated Player contracts pass independent and workspace strict SFC checks with no final JavaScript fallback or type escape. |
| US5 — Contributors migrate incrementally without breaking the main line | a–i | Every wave records one DOM owner, passes focused build/type/browser/visual evidence, and removes temporary mechanisms by its named expiry. |
