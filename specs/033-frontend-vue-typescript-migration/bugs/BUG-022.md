# Bug Report: Compatibility gate contradicts strict player-config decoding

**Type**: Spec conflict

## Description

The persistence gate requires compatible unknown fields to survive in both session and player-configuration documents. The canonical version-1 contracts intentionally differ: sessions retain unknown fields at the session, terminal, and recursive node levels, while player configurations use `json.Decoder.DisallowUnknownFields` and reject unknown top-level and roster fields. T088 may change only the fixture route/checker and cannot alter either production codec.

## Root Cause Analysis

Planning generalized the session codec's forward-compatible extras behavior across both JSON document types despite the player-config codec's explicit strictness and existing negative tests.

## Recommended Fix

Keep the exact four reviewed fixtures. Put compatible unknown fields only in session fixtures, use the legacy player fixture to prove absent-field defaults, and make the checker prove that synthesized unknown player-config fields remain rejected.
