# Bug Report: Canonical protobuf drift task omits its governed target contract

**Type**: Workflow contract
**Severity**: High
**Feature**: 033-frontend-vue-typescript-migration
**Reported**: 2026-09-01
**Status**: Patched
**Patched**: 2026-09-01

## Description

The T177 protobuf suite stops at `task proto:drift:check` because the canonical Taskfile target
invokes `scripts/proto-drift-test.sh` without the required generated TypeScript target and expected
diagnostic. The script correctly rejects the incomplete invocation, so the repository-wide
protobuf and CI quality workflows cannot exercise their promised deterministic drift check.

## Artifact Traceability

### spec.md

- **Affected user stories**: User Story 3 — retain deployable applications; User Story 5 — retain
  migration ownership and evidence integrity.
- **Affected requirements**: FR-012, FR-013, FR-034, FR-040, FR-049; SC-004, SC-010.
- **Gap identified**: The canonical drift gate is named but its required governed target contract
  is not carried by the Taskfile invocation.

### plan.md

- **Affected section**: Wave-i protobuf generation and contract exit.
- **Impact**: The Taskfile must bind the drift self-test to the reviewed Player protobuf output and
  its exact actionable diagnostic before the complete suite can be accepted.

### tasks.md

- **Affected task**: T177.
- **False completions**: None; T177 remains open and correctly stopped at the failing gate.
- **Missing scope**: T177 must be allowed to correct only the `proto:drift:check` Taskfile command
  before rerunning all six protobuf gates.

## Root Cause Analysis

The drift script was hardened to require explicit `--target` and `--expect-diagnostic` arguments,
but the canonical Taskfile caller retained the earlier argument-free command. Direct self-tests
covered the script while no contract test exercised the final task invocation after that change.

## Recommended Fix

Pass the reviewed generated Player protobuf file and its exact governed drift diagnostic from
`proto:drift:check`, then rerun the complete T177 protobuf suite and generated-tree clean diff.
