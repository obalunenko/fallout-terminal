# Bug Report: Public-access Vue slices omit required integration owners

**Type**: Spec conflict
**Severity**: High
**Feature**: `033-frontend-vue-typescript-migration`
**Reported**: 2026-08-30
**Status**: Patched
**Patched**: 2026-08-30

## Description

Tasks T064–T068 require the public-access status panel and four dialog families to become Vue-owned and to pass focused production-coexistence browser assertions. Their declared `Files` inventories omit `frontend/overseer/src/App.vue` and `frontend/overseer/src/index.html`, so the new components cannot be mounted and the existing legacy elements with the same IDs cannot be removed. T064 additionally lists its focused browser spec as read-only even though the RED contract currently assumes an impossible mount location and must be aligned with the governed Teleport leaf used inside the still-legacy layout.

The task file's path rule declares each `Files` list to be the complete writable inventory. Implementing the stated outcomes would therefore either violate the task contract or leave duplicate/unmounted DOM owners, conflicting with the feature's single-owner requirements.

## Root Cause Analysis

Task regeneration preserved the public-access component files and legacy JavaScript owners but omitted the already-established coexistence integration pattern used by earlier Vue leaves. The omission conflicts with the task-level complete-inventory rule and was not caught by BUG-002 through BUG-013, which corrected the same integration class for prior leaf families.
