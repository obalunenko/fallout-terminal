# Bug Report: Terminal-navigation failures disappear with the resolved dialog

**Type**: Implementation drift
**Severity**: High
**Feature**: 033-frontend-vue-typescript-migration
**Reported**: 2026-08-31
**Status**: Patched
**Patched**: 2026-08-31

## Description

When an approved terminal-navigation target becomes stale, the navigation composable closes the resolved dialog and retains the failure only in that dialog's local state. The persistent coordination alert remains empty, so the Overseer loses the actionable failure while correctly keeping the source terminal active.

## Artifact Traceability

### spec.md

- **Affected user story**: User Story 2 — Overseer migration.
- **Affected requirements**: FR-015, FR-022, FR-027, FR-050.
- **Gap identified**: Navigation command completion was not projected through the application controller.

### plan.md

- **Affected sections**: Wave e navigation approval and controller integration.
- **Impact**: Safe command failures must outlive the closed confirmation dialog in the persistent coordination surface.

### tasks.md

- **Affected task**: T093.
- **False completions**: None; earlier focused navigation checks did not exercise a target removed between request and approval.
- **Missing scope**: T093 must route navigation completion through the controller.

## Root Cause Analysis

The migrated composable subscribed directly to coordination events but never dispatched its command result to the controller that owns persistent feedback.

## Recommended Fix

1. Inject the Overseer controller into the navigation approval composable.
2. Dispatch the applicable command result before the local dialog lifecycle completes.
3. Retain canonical state application and persistent safe error projection.
4. Rerun the complete navigation and T093 suites.
