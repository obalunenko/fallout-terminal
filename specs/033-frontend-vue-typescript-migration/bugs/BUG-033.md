# Bug Report: Wave-e scanners retain deleted Overseer source assumptions

**Type**: Implementation drift
**Severity**: High
**Feature**: 033-frontend-vue-typescript-migration
**Reported**: 2026-08-31
**Status**: Patched
**Patched**: 2026-08-31

## Description

The T106 Wave-e exit reaches two deterministic validation scripts that were not migrated with the
Overseer cutover. `scripts/secret-leak-check.sh` still reads the deleted `overseer.js` and
`desktop-api.js` files for secret mutation, one-time password clearing, and secure-store wording.
`scripts/wails-v3-cutover-check.sh` scans the migration's own policy-checker regex literals as though
they were active Wails runtime commands. Both gates therefore fail after the required Vue-only
cutover even though the corresponding production behavior and browser evidence pass.

## Artifact Traceability

### spec.md

- **Affected user story**: User Story 3 — Build, package, and serve both migrated applications.
- **Affected requirements**: FR-026, FR-034, FR-035, FR-040, FR-046; SC-008 and SC-010.
- **Gap identified**: Final acceptance requires migrated deterministic scanners, but their legacy
  source consumers were not assigned to a writable Wave-e task.

### plan.md

- **Affected sections**: Producer and Consumer Impact Map; Wave e complete Overseer cutover.
- **Impact**: Cutover scanners must validate Vue components/composables and exclude only the exact
  checker implementation whose forbidden-pattern fixtures are not active runtime surfaces.

### tasks.md

- **Affected task**: T106.
- **False completions**: None; T106 is still open and correctly stopped on the stale consumers.
- **Missing scope**: T106 must be allowed to migrate `scripts/secret-leak-check.sh` and
  `scripts/wails-v3-cutover-check.sh` before rerunning the Wave-e exit.

## Root Cause Analysis

The task graph updated bundle, embed, package, and reset-smoke consumers but classified the final
secret and Wails cutover scanners as read-only integration inputs. Their source-level probes still
targeted files deleted by T090, and the Wails scanner did not exclude the exact policy checker added
by the migration itself.

## Recommended Fix

1. Patch T106 with a narrow normative scope override for the two scanners.
2. Replace legacy secret probes with exact Vue production owners and preserve the existing browser
   non-readback/clearing assertions.
3. Exclude only `scripts/frontend-policy-check.sh` from the active-command documentation scan while
   retaining its production-source enforcement through its own gate.
4. Rerun both scanner self-tests and real-tree checks, then resume the complete Wave-e exit.
