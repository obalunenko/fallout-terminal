# Bug Report: Overseer cutover removes the only application-state owner

**Type**: Spec conflict
**Severity**: Critical
**Feature**: `033-frontend-vue-typescript-migration`
**Reported**: 2026-08-31
**Status**: Patched
**Patched**: 2026-08-31

## Description

T089 requires production to select one Vue root with no coexistence bridge or legacy controller, and T090 deletes the legacy/candidate mechanisms. However, the completed leaf migrations intentionally leave terminal authoring, grouping, coordination convergence, dialog orchestration, and privileged command dispatch in `overseer.js`. Twenty-four current Vue source files still consume the temporary bridge, but T089 lists only seven Overseer source files as writable and does not include a replacement typed application controller. Removing the bridge and legacy owner therefore leaves the promoted application unable to load or mutate session state.

T090 also deletes `test-fixtures/candidate-main.ts`, while 15 retained browser suites import that exact entry and are read-only under T090/T093. Those suites cannot execute after the required deletion.

## Artifact Traceability

### spec.md

- **Affected user stories**: User Story 2 (privileged Overseer controls), User Story 4 (strict component applications), and User Story 5 (safe migration).
- **Affected requirements**: FR-001, FR-002, FR-004, FR-006, FR-010, FR-022, FR-031, FR-032, FR-033, FR-046, and FR-050; SC-001, SC-002, SC-011, and SC-012.
- **Gap identified**: One-root promotion has no typed owner for state/actions after the explicitly retained legacy domain owner is unselected.

### plan.md and migration-ownership.md

- **Affected sections**: Wave-e atomic promotion/removal and every T077–T086 ownership row that retains detached projections or domain dispatch in `overseer.js`.
- **Impact**: A final Vue-owned application controller/channel and explicit migration of all bridge consumers are required before legacy removal.

### tasks.md

- **Affected tasks**: T089, T090, and T093.
- **False completions**: None.
- **Missing scope**: T089 must own the new typed application controller/channel and every production bridge consumer it converts. T090 must own migration of all retained candidate-import browser harnesses (or provide a production-root replacement before deleting the candidate entry). T093 cannot remain read-only if selectors/bootstrap helpers require the new production route.

## Root Cause Analysis

Task generation treated already-migrated visual leaves as self-sufficient application slices even though their ownership records explicitly retain application-domain mutation and projection production in the legacy monolith. It also tracked candidate selection files but not downstream test imports of the candidate entry.

## Recommended Fix

Choose and encode one final architecture before T089:

1. Add a strict typed Overseer application controller/channel that owns the remaining session, terminal, group, coordination, and dialog state/action flow inside Vue.
2. Expand T089's writable inventory to every bridge-dependent production source converted to that channel.
3. Expand T090's inventory to the 15 affected browser suites and replace candidate-entry injection with the production root/entry before deleting the candidate mechanism.
4. Keep the one-root, no-authored-JavaScript, no-coexistence, and full-parity outcomes unchanged.
