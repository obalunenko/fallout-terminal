# Bug Report: Production desktop adapter parity was masked by the deleted facade

**Type**: Implementation drift
**Severity**: High
**Feature**: 033-frontend-vue-typescript-migration
**Reported**: 2026-08-31
**Status**: Patched
**Patched**: 2026-08-31

## Description

After BUG-024 switched `desktop-api.spec.mjs` to the production TypeScript adapter, three retained contracts failed: a late getter snapshot overwrote newer unrevisioned server/client events, terminal-switch command results lacked the established empty `status`/`switchId` normalization, and the hot-disposal assertion imported the deleted JavaScript facade instead of disposing the production adapter.

## Artifact Traceability

### spec.md

- **Affected user story**: User Story 2 — Overseer migration.
- **Affected requirements**: FR-014, FR-015, FR-022, FR-027, FR-050.
- **Gap identified**: Existing adapter parity was not exercised independently of the legacy facade.

### plan.md

- **Affected sections**: Typed desktop boundary and Wave-e final parity.
- **Impact**: Preserve event-before-snapshot precedence, switch-result defaults, and exact disposal on the production adapter.

### tasks.md

- **Affected task**: T093.
- **False completions**: None; T092 proved compilation/build, not these runtime semantics.
- **Missing scope**: T093 must correct `desktop-api.ts` alongside its newly writable adapter browser test.

## Root Cause Analysis

Earlier browser assertions still invoked `window.desktopAPI`, so their passing results did not cover the production TypeScript adapter for these flows.

## Recommended Fix

1. Suppress a getter field after a valid newer event for every runtime-status subscription.
2. Restore normalized terminal-switch result defaults.
3. Expose and invoke production adapter disposal in the browser test.
4. Rerun the complete desktop adapter suite and T093 parity command.
