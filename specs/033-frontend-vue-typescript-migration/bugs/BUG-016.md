# Bug Report: Runtime-shell GREEN omits required document and session owners

**Type**: Spec conflict
**Severity**: High
**Feature**: `033-frontend-vue-typescript-migration`
**Reported**: 2026-08-31
**Status**: Patched
**Patched**: 2026-08-31

## Description

T077 requires the Vue runtime shell to become the exclusive owner of the start/layout/header runtime presentation while removing the matching legacy header queries, subscriptions, URL handler, and session-label mutation. Its complete writable inventory omits `frontend/overseer/src/index.html`, so the legacy header markup cannot be replaced by the explicit empty Teleport target needed for single ownership. It also omits `frontend/overseer/src/composables/useSessionDocument.ts`, the existing owner of successful open/new document results, so the new runtime header cannot receive the acquired session filename without inspecting legacy DOM or duplicating the document command. The T076 RED locates the future header as an ordinary descendant of the Vue root; once the required target is added, Teleport moves the owned DOM to that target, so T077 also needs authority to align this locator without weakening any behavioral assertion.

The path rule makes these omissions a direct conflict: implementing the declared GREEN behavior would either modify undeclared files, leave duplicate header IDs/owners, or derive session state through prohibited cross-root DOM access.

## Root Cause Analysis

Task generation listed the new shell components/composables and the legacy JavaScript owner but missed the two established integration seams: production document markup is the current header owner, and `useSessionDocument` is the only typed owner that observes the successful document result and its filename. The omission would recreate the mixed-ownership problem corrected for earlier Wave-d leaf families.
