# Bug Report: Null broadcast state blocks player deletion confirmation

**Type**: Implementation drift
**Severity**: High
**Feature**: 033-frontend-vue-typescript-migration
**Reported**: 2026-08-31
**Status**: Patched
**Patched**: 2026-08-31

## Description

The production controller opens player deletion only when the coordination snapshot's `broadcast` field is `undefined`. The authoritative inactive representation is also `null`, so normal non-broadcast player-management state silently suppresses the deletion confirmation.

## Artifact Traceability

### spec.md

- **Affected user story**: User Story 2 — Overseer migration.
- **Affected requirements**: FR-015, FR-022, FR-027.
- **Gap identified**: The controller did not preserve the established null/absent equivalence for inactive broadcast state.

### plan.md

- **Affected sections**: Wave e controller integration and player-management parity.
- **Impact**: Player deletion remains disabled only for an actual active broadcast record, not for `null` or absent state.

### tasks.md

- **Affected task**: T093.
- **False completions**: None; focused ownership checks did not activate deletion from a null-broadcast snapshot.
- **Missing scope**: T093 must correct the production controller guard.

## Root Cause Analysis

The controller used an `undefined` identity check instead of validating whether `broadcast` is an active record.

## Recommended Fix

1. Treat only a broadcast record as active.
2. Permit deletion confirmation for both null and absent inactive values.
3. Rerun the complete player-management suite and T093 parity.
