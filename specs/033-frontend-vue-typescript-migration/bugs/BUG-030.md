**Type**: Implementation drift

## Description

Production-root authoring and approval parity exposed three controller integration gaps: a null broadcast was projected as active, controller `session-save-status` messages had no Vue consumer, and a command-approval failure remained only in the dialog that closes after resolution. The retained authoring test also still read the deleted `overseer.js` and asserted empty coexistence leaves after the single root was unmounted.

## Root Cause Analysis

The cutover replaced the legacy save-status DOM writer without adding a Vue subscriber, reused an undefined-only broadcast check, and kept approval errors local to a dialog whose canonical request immediately disappears. Mechanical test migration also missed source and cleanup assertions tied to coexistence.

## Recommended Fix

1. Treat only a broadcast record as active in authoring projections.
2. Render controller `session-save-status` messages in the production shell.
3. Dispatch approval command completion through the controller so safe failure feedback persists.
4. Inspect the typed controller instead of deleted legacy source and assert removed leaves are absent after unmount.
5. Rerun authoring, approval, and complete T093 parity.
