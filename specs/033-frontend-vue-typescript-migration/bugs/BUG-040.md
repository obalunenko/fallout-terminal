# Bug Report: Legacy static-asset Go tests survive the final Vue cutover

**Type**: Stale test ownership
**Severity**: High
**Feature**: 033-frontend-vue-typescript-migration
**Reported**: 2026-09-01
**Status**: Patched
**Patched**: 2026-09-01

## Description

The T180 repository-wide Go gate fails in `internal/platform/assets_test.go` because 30 historical
static-source tests still open deleted JavaScript owners (`client.js`, `sound.js`, `overseer.js`,
and `desktop-api.js`) or require the pre-Vue application markup to live directly in `index.html`.
The final Vue asset/embed contract tests and complete production browser suite pass, but these stale
tests keep the general Go suite red and falsely require removed coexistence sources.

## Root Cause Analysis

Wave-h migrated product behavior and production browser tests, while T165 updated the principal
Player Vue source/dist/embed inventory tests. The file also contained older behavior-oriented
static substring tests distributed throughout the suite; their legacy file dependencies were not
included in that cutover inventory and therefore survived until the unrestricted `go test ./...`.

## Recommended Fix

Remove exactly the legacy-only static-source tests that read deleted assets or pre-Vue `index.html`
markup, remove helpers left unused solely by those tests, retain the final Vue source/dist/embed and
boundary tests, then run `go fix`, review, `gofmt`, focused platform tests, and the full T180 chain.
