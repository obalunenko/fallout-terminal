# Bug Report: Retained parity fixtures lose their preloaded Overseer state before producer migration

**Type**: Spec conflict
**Severity**: High
**Feature**: 033-frontend-vue-typescript-migration
**Reported**: 2026-08-31
**Status**: Patched
**Patched**: 2026-08-31

## Description

After T090 replaces the coexistence document with the production `#overseerApp`, the retained player-management and public-access fixtures can no longer preload the main layout by rewriting legacy HTML attributes. The public-access ordering test also tries to defer its fake getter before any surviving module has installed the fixture bindings. T096 owns removal of those raw Go producer rewrites, but T093 runs the affected suites first.

## Artifact Traceability

### spec.md

- **Affected user story**: User Story 2 — Overseer migration.
- **Affected requirements**: FR-004, FR-030, FR-046, FR-051.
- **Gap identified**: The permanent production-root harness did not preserve established preloaded-fixture setup after the legacy document and facade were removed.

### plan.md

- **Affected sections**: Wave e removal and parity sequencing.
- **Impact**: The test-only harness must acquire a session for fixture routes that historically started loaded, while the ordering test must install fake bindings before deferring its getter.

### tasks.md

- **Affected tasks**: T090, T093, and T096.
- **False completions**: None; T090 correctly removed the legacy runtime and installed the permanent harness.
- **Missing scope**: T093 needs a narrow correction to the permanent harness and public-access ordering bootstrap; T096 retains the Go fixture-producer rewrite removal.

## Root Cause Analysis

The old Go fixture producer changed `display` attributes in legacy markup and relied on `desktop-api.js` to import the fake bindings. Neither mechanism exists in the single-root Vue document, and the task graph runs functional parity before the producer migration that removes those assumptions.

## Recommended Fix

1. Have the permanent test-only harness request the established fixture session on only the historically preloaded player-management and public-access routes.
2. Import the fake desktop bindings before deferring the public-access getter in the ordering test.
3. Leave the Go fixture producer unchanged until T096.
4. Rerun the complete T093 parity command.
