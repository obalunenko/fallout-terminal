# Bug Report: Equal-version public-access events cannot replace the getter snapshot

**Type**: Implementation drift
**Severity**: High
**Feature**: 033-frontend-vue-typescript-migration
**Reported**: 2026-08-31
**Status**: Patched
**Patched**: 2026-08-31

## Description

The production adapter uses one version tracker for public-access getters and events. After the initial getter delivers version `[0, 0]`, a development-override event with the same version is discarded, although live events are authoritative over equal getter snapshots. The reverse ordering must remain fail-closed: an equal or older getter cannot replace a delivered event.

## Root Cause Analysis

The generic snapshot subscription recorded only the latest version and rejected all equal candidates, losing whether the accepted value came from a getter or a live event. Its component-wise comparison could also accept a lower leading version component when a later component increased.

## Recommended Fix

1. Compare version tuples lexicographically.
2. For public access only, accept an equal-version event after a getter.
3. Reject an equal/older getter after an event and retain strict revision behavior for application updates.
4. Rerun desktop and public-access parity.
