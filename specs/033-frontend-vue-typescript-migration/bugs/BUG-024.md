# Bug Report: Desktop adapter browser gate loads the deleted JavaScript facade

**Type**: Spec conflict
**Severity**: High
**Feature**: 033-frontend-vue-typescript-migration
**Reported**: 2026-08-31
**Status**: Patched
**Patched**: 2026-08-31

## Description

T090 unconditionally deletes `frontend/overseer/src/desktop-api.js`, but the T093 parity command includes `tests/browser/desktop-api.spec.mjs`, whose setup still waits for `window.desktopAPI` from the deleted file. The fixture producer is not scheduled for its Vue update until T096, so T093 cannot pass while the desktop test remains read-only.

### plan.md

### tasks.md

## Root Cause Analysis

The task graph treated raw facade removal and fixture-producer migration as independent, but T093 consumes a test whose setup directly depended on the removed facade before T096 could update the producer.

## Recommended Fix

1. Allow T093 to update only `tests/browser/desktop-api.spec.mjs` so it installs and aliases the production typed adapter through browser-test bindings.
2. Preserve T096 ownership of the broader Go fixture producer migration.
3. Run bugfix verification, then rerun the complete T093 parity command.
