## Description

The complete T106 browser gate passes 223 tests and skips the two credential-qualified ngrok tests,
but two retained Overseer suites fail only at their final unmount assertions. The broadcast suite
waits for deleted `#broadcastControlsVueLeaf`, and the hacking suite waits for deleted
`#hackControlsVueLeaf`. Production now has one `#overseerApp` root, so both absent locators time out
instead of proving that the production root is empty. Their revision, action, stale-suppression, and
subscription-release assertions all pass before this stale selector check.

## Root Cause Analysis

The production-root harness migration updated imports and mounting but the two suites were omitted
from T093's focused parity command. Their last assertions therefore retained coexistence-era leaf
selectors even though all other lifecycle logic used the production fixture.

## Recommended Fix

1. Permit T106 to replace the two deleted leaf locators with `#overseerApp`.
2. Keep the existing exact-once release assertion in the hacking suite.
3. Run both focused cleanup tests and the complete browser suite.
