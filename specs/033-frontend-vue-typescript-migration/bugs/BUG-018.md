# Bug Report: Opened session revision is absent from terminal-group mutations

**Type**: Implementation drift
**Severity**: High
**Feature**: `033-frontend-vue-typescript-migration`
**Reported**: 2026-08-31
**Status**: Patched
**Patched**: 2026-08-31

## Description

After the runtime-shell/session-document migration, opening a persisted session loads its document but does not transfer the authoritative saved session revision into the remaining terminal-group workflow. An immediate reviewed group reorder therefore sends `expectedSessionRevision: 0`; the backend rejects it as stale even though no user or external mutation occurred. The older dialog atomicity assertion counted the rejected command but did not require the intended canonical change, so it passed against unchanged state.

## Root Cause Analysis

The native session operation result carries the document and path but not its persistence revision. Before the shell migration, the temporary legacy facade could eventually learn that revision through a runtime snapshot. The migrated session-document path loaded the document immediately without refreshing and transferring the post-open runtime status, while the temporary facade returned its cached startup status. This allowed the group UI to prepare a valid candidate with an invalid expected revision.

## Recommended Fix

1. Patch T079 to include `useSessionDocument.ts` and the temporary `desktop-api.js` facade.
2. Refresh runtime status after document acquisition, validate `savedRevision`, and include it in the detached `session-document-loaded` request.
3. Initialize the legacy session revision from that request and strengthen the governed T079 assertion to require an actual canonical reorder.
4. Verify artifact consistency, then resume T079.
