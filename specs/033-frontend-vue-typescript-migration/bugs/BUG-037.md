# Bug Report: Native reset verifier searches for deleted legacy evidence

**Type**: Implementation drift
**Severity**: High
**Feature**: 033-frontend-vue-typescript-migration
**Reported**: 2026-08-31
**Status**: Patched
**Patched**: 2026-08-31

## Description

After BUG-036 lets the packaged reset journey traverse completed-command approval, the reset
succeeds: the selected terminal's canonical `commandStates` are removed, the other terminal is
unchanged, and controller plus observer converge from runtime revision 11 to 12 in 5 ms. The smoke
then fails because `verify_native_overseer_reset` still searches the Accessibility tree for the
legacy `overseer.js` aria prose `Wails command ResetTerminalCommandStates ok`, `document revision`,
and `session-state revision`. Those deleted dataset fields are not produced by the Vue application,
which exposes the canonical reset success text and saved revision through `#saveStatus`.

## Root Cause Analysis

The native smoke's source-presence checks were migrated to Vue during the cutover, but its runtime
Accessibility predicate was left unchanged. It therefore requires strings that no production
source emits even after all externally observable reset effects have succeeded.

## Recommended Fix

1. Find the Vue-owned reset success text and revision in the native Accessibility tree.
2. Retain the disabled reset button, exact canonical file mutation, other-terminal preservation,
   Player convergence, shared navigation, and full-reopen assertions.
3. Update diagnostics to name the Vue status/revision contract and rerun the packaged journey.
